## 4. HARD-EDGE CONSTRUCTION TRACE

**CODE_PATH_PROVED:** `indexer.py:231-260` visits `ast.Import` and `ast.ImportFrom` into `ImportRef(module,level,names,is_from_import,is_local,type_only)` (`domain/imports.py:12-27`). Relative syntax retains `level`; function depth sets `is_local`; the shown visitor does not set `type_only`. File module ID is `".".join(rel.with_suffix("").parts)` (`indexer.py:389-393`), hence `pkg/__init__.py` is indexed as `pkg.__init__`. `ContextorFacade.analyze_project` gets the graph via `get_cached_graph(... build_graph(...))` (`facade.py:744-767`). `ProjectGraph` has `hard_edges: dict[str,set[str]]`, `soft_edges: dict[str,set[str]]` (`domain/graph.py:11-19`). `build_graph` has effective signature `build_graph(modules: dict[str,Module], trie: dict|None=None, package_root: str|None=None, progress_callback=None, reexport_facts_by_module: dict|None=None) -> ProjectGraph` (`graph.py:111-117`); the earlier `build_graph` definition at `:93-109` is overwritten by this second definition in Python. `build_graph` seeds a key for every module and calls `resolve_module_edges` (`graph.py:153-183`).

**CODE_PATH_PROVED:** `resolve_internal(imp: ImportRef,trie: TrieNode,current_module_id: str,package_root: str|None) -> ResolutionResult` (`resolver.py:254-330`) first normalizes relative level with `_resolve_relative_base` / `_normalize_relative` (`:190-225`), optionally strips detected package-root prefix, then exact trie lookup. If `pkg` itself is not a module key, it tries `pkg.__init__` (`:282-295`). Longest-prefix and imported-symbol fallbacks are `FALLBACK`, not exact `MODULE` (`:300-329`). `resolve_module_edges` (`graph.py:185-304`) adds exact `MODULE` targets to hard edges, `FALLBACK` to soft edges, type-only to soft edges, ignores `UNKNOWN`/resolver exceptions, and drops self edges in `_add_edge` (`:69-85`). It does not suppress function-local imports; the sorted `is_local` fact is not used to distinguish hard/soft at `:211-230`. Control guards are not represented in `ImportRef`, so guarded import activation is not proved by a hard edge. Implicit parent initialization does **not** create a hard edge for a plain dotted import; F1 directly shows `pkg.a -> pkg.b` without `pkg.a -> pkg.__init__`.

Current mapping for each requested syntax (assuming the module IDs in F1/F2; missing modules, re-export bindings and package-root stripping can alter the result):
